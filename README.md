# NavigatorMAX

**Кружки и секции для ребёнка — через диалог в Сферуме.**

NavigatorMAX — чат-бот для поиска программ дополнительного образования на естественном языке. Родитель описывает интересы ребёнка, возраст и свободное время, а бот находит подходящие группы в выгрузке регионального Навигатора ([Региональный Навигатор Ростовской области](https://new-portal.ris61edu.ru/)), показывает расписание и объясняет выбор.

> «Найди рисование для ребёнка 10 лет во вторник после 14:00»

В основе решения — **базовый RAG**: GigaChat понимает запрос и составляет объяснения по найденным данным, а Python проверяет ограничения и формирует карточки из базы. Для подачи заявки бот даёт ссылку на программу в региональном Навигаторе.

**Текущий пилот:** Ростовская область → Ростов-на-Дону. Архитектура предусматривает подключение других муниципалитетов и регионов.

Готовый Docker-образ: [Docker Hub](https://hub.docker.com/r/boriskolegaev/navigatormax).

## Задача проекта

При выборе дополнительного образования родителю приходится сопоставлять содержание программ, возрастные ограничения и расписания отдельных групп. Название интересующего занятия не всегда совпадает с названием программы в каталоге.

NavigatorMAX добавляет к региональному каталогу диалоговый интерфейс: можно сформулировать запрос своими словами, уточнить условия следующим сообщением и получить несколько вариантов со ссылками на источник. Оформление записи остаётся в региональном Навигаторе.

## Возможности

* **Поиск по интересам:** название занятия, технологии или направление, например Python или рисование.
* **Подбор по возрасту:** проверка возрастного диапазона конкретной группы.
* **Проверка расписания:** дни недели и удобный интервал времени.
* **Поиск по организации или преподавателю:** если они названы в запросе.
* **Выбор территории кнопками:** сначала область, затем муниципалитет.
* **Уточнение в диалоге:** например, «а после 16?» с сохранением остальных условий.
* **Объяснение рекомендаций:** модель кратко описывает, почему выбранный вариант соответствует запросу.
* **Карточки из базы:** название программы и группы, организация, возраст, преподаватель, адрес, описание, расписание и ссылка.
* **Проверка условий записи:** статусы программы и группы, сроки приёма, завершение обучения и опубликованные сведения о свободных местах.
* **Резервная выдача:** при ошибке второго обращения к модели бот показывает найденные карточки без объяснений.

## Как работает RAG

### 1. Разбор запроса

Первое обращение к GigaChat преобразует сообщение в структурированные условия: возраст, ключевые слова, преподаватель, организация, дни недели и границы времени. Для уточнений передаются предыдущие условия диалога. Формат и допустимые значения проверяются кодом.

### 2. Поиск в каталоге

Python скрипт отбирает группы выбранного региона и муниципалитета. Поиск использует нормализованный текст названия, текст описания и учебного плана; модель при разборе запроса может предложить близкие ключевые слова. Совпадения в названии программы получают больший вес при ранжировании.

Возраст, расписание и признаки открытой записи проверяются программно. Если задано свободное время, **все учитываемые занятия группы должны помещаться в выбранные дни и интервал**. Группы с неполным расписанием при таком запросе исключаются из выдачи.

### 3. Генерация объяснений

Второе обращение получает исходное сообщение, действующие условия и до пяти подготовленных карточек. Модель выбирает до трёх вариантов и возвращает их идентификаторы с короткими объяснениями. Код проверяет, что идентификаторы существуют в переданной подборке и не повторяются.

Расписания, адреса и ссылки подставляются из базы. Инструкции ограничивают объяснения переданными сведениями; это снижает риск выдуманных фактов, но не заменяет проверку качества ответов.

В этой реализации **нет векторной базы и эмбеддингов**: извлечение данных выполняется текстовым поиском и фильтрами. RAG обеспечивается передачей результатов поиска модели для генерации объяснений. При пустой выдаче или запросе уточнения второе обращение не выполняется.

## Источник данных

Парсер [Parser/navigator_export.py](Parser/navigator_export.py) обращается к публичным JSON-эндпоинтам [Навигатора Ростовской области](https://new-portal.ris61edu.ru/) и собирает данные по цепочке **организация → программа → группа**. Сохраняются исходные поля, текстовые сведения, нормализованные расписания и ссылки на карточки.

[Inlearno — «Навигатор дополнительного образования детей»](https://inlearno.ru/dod) описывает платформу региональных навигаторов и содержит ссылки на региональные внедрения. Распределение каталогов по регионам позволяет развивать тот же сценарий подбора для других территорий; совместимость конкретного источника с парсером проверяется при подключении.

Данные бота — **снимок каталога на момент выгрузки**. Дата завершения обхода сохраняется в `_meta.finished_at` и указывается в ответе с результатами. Свободные места и правила приёма могут измениться после выгрузки; актуальные условия и подачу заявки пользователь проверяет по ссылке в региональном Навигаторе.

## Запуск

### Требования

* Python **3.11 или новее**.
* Доступ к интернету для MAX, GigaChat и, при обновлении данных, регионального Навигатора.
* Токен бота MAX и ключ авторизации GigaChat API с доступом к выбранной модели.
* JSON-выгрузка каталога. Её можно подготовить входящим в репозиторий парсером. В докере уже есть файл с выгрузкой.

Локальная LLM и видеокарта не требуются. Парсер использует стандартную библиотеку Python; внешние зависимости нужны боту.

### 1. Получить проект и установить зависимости

```bash
git clone https://github.com/BorisKolegaev/NavigatorMAX.git
cd NavigatorMAX
python -m pip install gigachat maxapi
```

### 2. Заполнить конфигурацию

В файле `configuration/config.txt` указать значения в формате `КЛЮЧ=ЗНАЧЕНИЕ`:

### 3. Подготовить данные

Из корня проекта выполнить выгрузку Ростова-на-Дону:

```bash
python Parser/navigator_export.py --municipality 1 --output rostov.json
```

Скрипт использует [Parser/municipality.txt](Parser/municipality.txt), где ID `1` соответствует Ростову-на-Дону. Указывать файл муниципалитетов отдельно не требуется. После успешного завершения `rostov.json` появится в Parser, бот же загружает json из корня проекта.

Если готовая совместимая выгрузка уже есть, достаточно разместить её под этим именем рядом с `bot.py`. Вместе с исходным кодом рабочая база не поставляется (в докере есть выгрузка).

## Примеры запросов

| Запрос | Что учитывает бот |
| --- | --- |
| «Рисование для ребёнка 10 лет во вторник после 14:00» | Содержание, возраст, день и начало свободного интервала |
| «Python утром в понедельник и среду» | Технологию, дни и интервал 08:00–12:00 |
| «Занятия у Иванова для ребёнка 12 лет» | Фамилию преподавателя и возраст |

Наличие результатов зависит от выгрузки. Если возраст не указан, бот предлагает его уточнить; если подходящих групп не найдено — изменить или уточнить условия.

### Команды и кнопки

| Действие | Результат |

| `/start` | Начать с выбора области и муниципалитета |

| `/new` или «🔎 Новый подбор» | Сбросить условия поиска, сохранив выбранную территорию |

## Настройка RAG и расхода токенов

Основные ограничения заданы в начале `bot.py`:

| Параметр | По умолчанию | Что ограничивает |
| --- | --- | --- |
| `RAG_MAX_CANDIDATES` | `5` | Число карточек, рассматриваемых для второго обращения |
| `RAG_MAX_RECOMMENDATIONS` | `3` | Число выводимых рекомендаций |
| `RAG_MAX_CONTEXT_CHARS` | `12000` | Длину JSON с запросом, условиями и карточками **в символах**, без системного промпта |
| `RAG_MAX_DESCRIPTION_CHARS` | `900` | Длину фрагмента описания одной карточки |
| `RAG_MAX_PLAN_CHARS` | `450` | Длину фрагмента учебного плана одной карточки |
| `RAG_MAX_OUTPUT_TOKENS` | `1000` | Максимум выходных токенов второго обращения |
| `QUERY_MAX_OUTPUT_TOKENS` | `700` | Максимум выходных токенов разбора запроса |

## Парсер и обновление каталога

Парсер собирает отдельные JSON-снимки и рассчитан на возобновление прерванного обхода. Он сохраняет контрольную точку в SQLite, использует паузы между запросами и повторы временных ошибок. Успешный снимок публикуется через временный файл; перед заменой существующей базы создаётся резервная копия `.bak`.

Для обновления данных повторить команду с теми же параметрами:

```bash
python Parser/navigator_export.py --municipality 1 --output rostov.json
```

После обновления **перезапустить бота**: каталог загружается в память при старте, автоматической перезагрузки в текущей версии нет.

| Параметр парсера | Назначение |
| --- | --- |
| `--municipality 1` | Выгрузить один муниципалитет |
| `--municipality 1,2` | Выгрузить несколько ID из файла муниципалитетов |
| `--municipalities FILE` | Использовать другой список территорий в формате `Название, ID` |
| `--output FILE` | Указать итоговый JSON; без параметра используется `navigator.json` |
| `--state FILE` | Указать SQLite-файл контрольной точки; по умолчанию `<output>.state.sqlite3` |
| `--sample N` | Пробная неполная выгрузка первых N программ; требует одного муниципалитета и отдельного выходного файла |
| `--restart` | Начать заново незавершённый обход |
| `--delay`, `--jitter` | Настроить паузы между запросами; минимальный `--delay` — 1 секунда |
| `--timeout`, `--retries` | Настроить сетевой тайм-аут и число повторов |

Все параметры и их значения по умолчанию:

```bash
python Parser/navigator_export.py --help
```

Без `--municipality` скрипт обходит все территории из указанного файла. Для другого набора территорий или пробной выборки используйте **другой `--output`**: парсер проверяет совместимость области выгрузки с уже существующим JSON. Флаг `--restart` не отменяет эту проверку.

Снимок содержит `_meta` с источником, датой и статистикой, список `municipalities`, иерархию `organizations` и отчёт `changes`. Статус `complete` означает завершённый обход выбранных территорий. Отсутствие записи в новом снимке (`not_seen`) само по себе не доказывает её удаление из исходной системы.

## Масштабирование на другие регионы

**Решение можно масштабировать на другие регионы России.** Бот отделяет логику диалога и подбора от региональных данных: каждая запись `REGION_SETTINGS` указывает собственную выгрузку, доступные муниципалитеты и шаблон ссылки на программу. При поиске учитываются и регион, и муниципалитет, поэтому одинаковые локальные ID разных регионов не смешиваются.

### Добавление муниципалитета в текущий регион

1. Подготовить выгрузку, включающую нужные территории. Например, для Ростова-на-Дону и Таганрога:

   ```bash
   python Parser/navigator_export.py --municipality 1,2 --output rostov_extended.json
   ```

2. В записи региона `"61"` в `REGION_SETTINGS` указать `"data_file": "rostov_extended.json"` и расширить список:

   ```python
   "municipalities": {
       "1": "Ростов-на-Дону",
       "2": "Таганрог",
   },
   ```

3. Перезапустить бота. Муниципалитет появится в меню.

### Подключение другого региона

1. Найти региональный портал и проверить его публичные эндпоинты, поля программ, групп и расписаний. Информацию о региональных внедрениях можно получить на [сайте Inlearno](https://inlearno.ru/dod).
2. Подготовить адаптер источника. Сейчас `BASE_URL` в `Parser/navigator_export.py` задан для Ростовской области; у скрипта **нет параметра `--base-url`**. Для совместимого API потребуется настройка адреса и списка муниципалитетов, а при отличиях API — адаптация запросов и преобразования данных.
3. Сохранить результат в той же структуре JSON: `_meta`, `municipalities`, `organizations` с программами и группами.
4. Добавить запись в `REGION_SETTINGS`, указав название региона, файл данных, ID доступных муниципалитетов и `program_url_template` для ссылок на его портал.
5. Проверить часовой пояс, статусы записи, расписания и поиск на контрольных запросах, затем перезапустить бота.

Текущая обработка дат ориентирована на московское время (`Europe/Moscow`, UTC+3). Для регионов с другим часовым поясом интерпретацию дат и времени нужно адаптировать. Общая концепция диалога и RAG при подключении нового региона сохраняется; совместимость произвольных порталов без адаптации не предполагается.
